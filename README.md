# BallCombination

네이버 스포츠 KBO 문자중계에서 **투구 단위 데이터(구종, 구속, 투구 위치, 궤적)** 를 수집하는 크롤러.

## 설치

```bash
pip install -r requirements.txt
```

## 사용법

```bash
# 기간 지정: 해당 기간에 종료된 KBO 정규시즌/포스트시즌 경기를 모두 수집
python -m kbo_crawler.crawl --from 2025-09-01 --to 2025-09-07 --out data/pitches_0901_0907.csv

# 경기 지정 (gameId는 네이버 경기 URL에 있는 값, 예: 20250920LGSS02025)
python -m kbo_crawler.crawl --game 20250920LGSS02025
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--from` / `--to` | | 수집 기간 (YYYY-MM-DD) |
| `--game` | | gameId 직접 지정, 여러 번 사용 가능 |
| `--out` | `data/pitches.csv` | 출력 CSV (Excel에서 한글이 깨지지 않게 UTF-8 BOM으로 저장) |
| `--cache` | `data/raw` | API 원본 JSON 캐시. 다시 실행하면 캐시를 재사용 |
| `--all-rounds` | 꺼짐 | 시범경기·올스타전도 수집 (기본은 정규시즌 + 포스트시즌만) |
| `--delay` | `0.7` | 요청 간 최소 간격(초) |

## 출력 컬럼

| 컬럼 | 설명 |
|---|---|
| `game_id`, `game_date`, `stadium`, `away_team`, `home_team` | 경기 정보 |
| `round_code` | `kbo_r` 정규시즌, `kbo_ps_*` 포스트시즌(`wd` 와일드카드, `sp` 준플레이오프 등) |
| `inning`, `half` | 이닝, `top`(초) / `bottom`(말) |
| `pitcher_id/name`, `batter_id/name`, `stance` | 투수, 타자, 타자 타석(L/R) |
| `balls`, `strikes`, `outs` | 투구 **직전** 볼카운트, 아웃 수 |
| `on_1b`, `on_2b`, `on_3b` | 투구 직전 1·2·3루 주자 유무 (1/0) |
| `away_score`, `home_score` | 투구 직전 점수 |
| `score_diff` | 투구 직전 점수차, **투수팀 기준** (+면 투수팀이 앞섬) |
| `pitch_num`, `pitch_result` | 타석 내 투구 번호, 결과 코드(B 볼, T 루킹 스트라이크, S 헛스윙, F 파울, H 타격 등) |
| `pitch_type`, `speed_kmh` | 구종, 구속(km/h) |
| `pa_result` | 그 투구가 속한 **타석의 최종 결과**: 삼진, 볼넷, 고의4구, 사구, 1루타, 2루타, 3루타, 홈런, 땅볼, 플라이, 라인드라이브, 병살타, 희생번트, 희생플라이, 실책출루, 야수선택, 번트아웃, 기타 |
| `pa_last_pitch` | 타석의 마지막 공(결정구)이면 1 |
| `pa_result_text` | 타석 결과 원문 (예: `황영묵 : 우익수 오른쪽 뒤 3루타`) |
| `plate_x`, `plate_z` | 홈플레이트 통과 위치(좌우, 지면으로부터 높이). 단위 ft, PITCHf/x 좌표계 |
| `sz_top`, `sz_bot` | 해당 타자 스트라이크존 상단/하단 |
| `x0..az` | 궤적 파라미터(초기 위치·속도·가속도) |
| `text` | 문자중계 원문 |

## 동작 방식

1. `GET https://api-gw.sports.naver.com/schedule/games?...&categoryId=kbo` 로 기간 내 경기 목록 조회
2. 경기마다 `GET /schedule/games/{gameId}/relay?inning=N` 을 1회부터 호출 (연장까지, 데이터가 없으면 중단)
3. 응답의 `textOptions`(구종/구속/카운트)와 `ptsOptions`(투구 추적 좌표)를 `ptsPitchId`로 매칭해서 한 행으로 만듦
4. `currentGameState`는 이벤트 **이후** 상태이므로, 투구 직전 상황(카운트, 아웃, 주자, 점수)은
   seqno 순으로 바로 앞 이벤트(타자 등장, 도루, 피치클락 위반 등 포함)의 상태를 사용
5. `ptsOptions.crossPlateY`는 높이가 아니라 홈플레이트 앞면까지의 거리(항상 약 0.708ft)이므로,
   투구 높이 `plate_z`는 궤적 파라미터(`y0, vy0, ay, z0, vz0, az`)로 홈플레이트 통과 시점을 구해 계산함
   (같은 방식으로 계산한 x가 네이버의 `crossPlateX`와 일치하는 것을 확인)

## 주의

- 네이버의 **비공식 내부 API**입니다. 응답 구조가 바뀌면 `kbo_crawler/parse.py`를 수정해야 합니다.
  원본 JSON이 `data/raw/{gameId}/` 에 남아 있으니 브라우저 개발자도구(Network 탭에서 `relay` 검색)와 비교해서 고치면 됩니다.
- 요청 간격을 너무 줄이지 마세요. 시즌 전체(약 720경기)는 1만 회 가까운 요청이 나갑니다.
- 수집한 데이터는 개인 분석이나 연구 용도로 쓰고, 재배포나 상업적 이용은 네이버 이용약관을 확인하세요.

## 웹 탐색기

`web/index.html`은 수집한 투구로 투수별 볼배합을 보는 페이지입니다.

- 상단 검색창에 투수 이름을 입력해 고르고, 선수 카드에서 핵심 지표와 구종 구성을 한눈에 봅니다
- 핵심 포인트 카드가 주무기, 삼진 잡는 결정구, 초구, 2스트라이크 이후 경향을 문장으로 요약합니다
- 자주 쓰는 상황(초구, 2스트라이크, 득점권, 결정구 등)은 버튼 한 번으로 걸고, 걸린 조건은 칩으로 지웁니다
- 화면은 투수 한눈에 / 다음 공 예측 / 가상 타석 / 직접 플레이 / 투수 컨디션 / 공의 움직임 / 구종 비교 / 상황별 구종 탭으로 나뉘고, 주소 끝의 #trajectory 같은 값으로 탭을 바로 열 수 있습니다

- **투구 위치**: 스트라이크존 위에 구종별 색으로 표시 (포수 시점, 타자별 존을 리그 평균 높이에 맞춰 정규화)
- **구종 구성**: 구종별 투구 수, 비율, 평균/최고 구속, 스트라이크%, 헛스윙%
- **결정구 결과**: 타석 마지막 공의 구종별 삼진%, 볼넷%, 피안타율
- **투구 궤적**: 포수 시점(원근), 옆, 위에서 본 궤적. 구종 평균 또는 개별 투구(최대 300개).
  재생 버튼으로 실제 비행 시간대로 공이 날아가는 모습을 실제 속도 또는 1/4 속도로 볼 수 있음
- **터널링**: 기준 구종과 다른 구종의 평균 궤적을 홈 도착 전 같은 시간에 맞춰 비교.
  릴리스 차이, 타자 판단 시점(홈 도착 0.167초 전) 차이, 홈 도착 차이, 갈라짐 배율(홈 차이 ÷ 판단 시점 차이)
- **무브먼트**: 구종별 수평/수직 무브먼트 분포와 평균 (투수를 고르면 팔 쪽/글러브 쪽 표시)
- **카운트별 볼배합**: 투구 직전 카운트 12가지마다 구종 비율
- **필터**: 팀, 투수, 타자 타석(좌/우), 카운트 상황, 투구 범위(결정구), 타석 결과, 주자, 아웃, 점수 상황, 월, 정규/포스트시즌

### 궤적과 무브먼트 계산 (`kbo_crawler/physics.py`)

- CSV의 `x0..az`는 PITCHf/x와 같은 9-파라미터 궤적 모델입니다. 위치 = 시작 위치 + 속도·t + 가속도·t²/2
- 무브먼트는 PITCHf/x 정의를 따릅니다. 홈에서 40ft 지점부터 홈플레이트까지, 중력만 받는 궤적 대비 더 움직인 거리(cm)
- 궤적은 측정 시작점(홈에서 50ft, 7월 중순 이후는 55ft)부터 그리고, 50ft 측정분의 릴리스 구간(54.5ft까지)은 같은 식으로 이어 그린 추정(점선)입니다
- 투수의 투구 손은 측정 시작 지점의 좌우 위치(x0) 중앙값 부호로 판단합니다
- 구장마다 측정 장비 보정 차이가 있습니다. 같은 투수도 구장에 따라 무브먼트가 ±5cm 정도 다르게 나옵니다
- **회전수(RPM)는 제공하지 않습니다.** 네이버 데이터에 회전수가 없고, 가속도로 추정해 보면 같은 투수의 직구도
  공마다 2,200~3,900rpm으로 흔들려 쓸 수 있는 값이 아니었습니다

```bash
python -m kbo_crawler.export_web "datasets/kbo_pitches/2026-*.csv" --out web/pitches.json   # web/traj/*.json 도 생성
cd web && python -m http.server 8000   # http://localhost:8000
```

## 볼배합 예측 (`kbo_crawler/predict.py`, `web/predict.js`)

투수·타자·카운트·타석·직전 구종으로 **다음 공의 구종 확률과 코스 확률**을, 같은 상황에서 구종별로
**실점을 얼마나 막았는지(투구 가치)**를 계산합니다. 탐색기의 "다음 공 예측" 탭에서 쓰고,
성능과 해석은 [`docs/prediction_report.md`](docs/prediction_report.md)에 정리했습니다.

```bash
python -m kbo_crawler.predict "datasets/kbo_pitches/2026-*.csv" --report docs/prediction_report.md
```

- 구종: 계층형 빈도 모델 (투수 → +카운트 → +타석 → +직전 구종, 기록이 적으면 넓은 상황 쪽으로 수축) + 타자별 보정.
  9~10월 검증에서 정답률 46.9%, 상위 2개 74.4% (최다 구종 찍기 44.4%)
- 코스: 존 9칸 + 바깥 4칸. 리그의 구종·투수 손·타석·카운트 경향에 투수 개인 경향을 곱함
- 투구 가치: 2026 기록으로 만든 기대 득점표(RE24)로 타석 결과·카운트의 가치를 구하고, 공 하나가 바꾼 가치를 평균
- 같은 계산을 브라우저(`web/predict.js`)와 파이썬이 하며, 두 결과가 같은지 `tests/test_predict.py`가 확인합니다

## 타석 시뮬레이션 (`web/simulate.js`)

탐색기의 "시뮬레이션" 탭에서 투수와 타자의 한 타석을 공 하나씩 진행합니다.

1. 구종: 예측 모델의 확률에서 뽑음 (볼배합 가정으로 초구·2스트라이크 구종을 고정할 수 있음)
2. 코스: 코스 모델에서 뽑고, 정확한 카운트별 리그 경향과 투수의 존 안 비율(제구)로 보정. 그 투수가 실제로 같은 구종·코스에 던진 공 하나로 구속과 궤적을 보여줌
3. 결과: 볼 / 루킹 스트라이크 / 헛스윙 / 파울 / 인플레이 / 사구. 리그의 (코스, 카운트, 구종) 비율에 타자·투수 성향을 곱함
4. 인플레이면 1루타~홈런, 땅볼, 플라이, 직선타, 실책 중 하나

볼넷·삼진·사구·인플레이가 나오면 타석이 끝납니다. 주자는 다루지 않습니다.
여러 타석을 돌리면 삼진·볼넷·피안타율·타석당 기대 실점을 실제 시즌 기록과, 볼배합 가정을 넣었을 때와 비교합니다.

보정 결과 (`tests/sim_calibration.js`, 2026 실제 타석 5.6만 개를 같은 투수·타자로 다시 시뮬레이션):

- 리그 전체 비율: 삼진·볼넷·안타·홈런·땅볼·플라이 모두 실제와 1%p 안팎, 타석당 투구 수 3.87 (실제 3.91)
- 300타석 이상 투수 59명의 삼진율·볼넷율: 실제와 상관 0.88~0.91, 기울기 0.73~0.76.
  한 시즌 기록에 섞인 우연까지 따라가지 않도록 일부러 평균 쪽으로 당긴 결과이고,
  제구가 아주 좋은 투수는 볼넷이 실제보다 1~2%p 많게 나옵니다

## 직접 해보기 (게임)

탐색기의 "직접 해보기" 탭에서 투수나 타자가 되어 한 타석을 겨룹니다. 판정은 모두 2026 기록에서 나옵니다.

- **투수로 던지기**: 그 투수의 실제 구종 중 하나를 고르고 노릴 곳을 누르면, 노린 곳 주변에서 그 투수가 그 구종으로
  실제 던진 공 하나가 날아갑니다(흩어짐 = 그 투수의 실제 위치 분산 × 0.6). 타자 반응은 시뮬레이터의 결과 모델이 정하고,
  노릴 곳 지도에는 이 타자를 상대로 코스별 기대 실점 변화가 색으로 표시됩니다
- **팀 타선 상대하기**: 투수 모드의 "상대"에서 팀을 고르면 그 팀 예상 라인업 1번부터 차례로 상대합니다.
  예상 라인업은 팀의 최근 20경기에서 경기마다 처음 타석에 선 9명을 그 경기 선발 1~9번으로 보고,
  (타자, 타순) 선발 횟수가 많은 쌍부터 겹치지 않게 채웁니다(`export_web.expected_lineups`).
  아웃·이닝·주자·실점이 이어지며, 진루는 단순 규칙(볼넷 밀어내기, 단타 때 2·3루 주자 득점, 2루타 때 1루 주자 3루, 범타는 진루 없음)을 따릅니다
- **타자로 치기**: 투수는 예측 모델대로 구종·코스를 고르고 실제 궤적으로 던집니다. 공이 홈에 닿을 때 지나갈 곳을
  클릭(탭)하면 스윙하고, 타이밍(±0.075초)과 위치(좌우 ±24cm, 높이 ±12cm) 오차로 헛스윙·파울·타구 질이 정해집니다.
  타구 결과는 그 타자의 실제 타구 분포를 타구 질만큼 장타 쪽으로 기울여 뽑습니다. 안 친 공은 2026 실제 판정 비율
  (ABS 도입 이후라 존 안은 사실상 100% 스트라이크)을 따릅니다. 공 속도는 1/3, 1/2, 실제 중에서 고릅니다
- 스윙 판정 폭과 타구 질 가중치는 게임 손맛을 위해 정한 값이고 데이터에서 추정한 값이 아닙니다

```bash
python -m kbo_crawler.workload --schedule 7                        # (네트워크 필요) 다음 7일 일정·예고 선발도 붙이기
```

- **경기 기록**: 문자중계 응답에 들어 있는 양 팀 박스스코어(투수: 이닝·투구 수·피안타·볼넷·삼진·자책, 타자: 타순·타석 결과)와
  그날 엔트리(나오지 않은 투수 포함)를 `datasets/kbo_games/pitching.csv`, `batting.csv`로 저장합니다. 네트워크 요청 없이 캐시만 읽습니다.
  박스스코어 투구 수는 투구 데이터와 7,125건 중 7,122건이 일치합니다(나머지 3건은 중계 원본 중복·누락)
- **불펜 피로도**: 그날 엔트리에 있던 구원 투수가 실제로 나왔는지(코칭스태프의 판단)를 연투, 전날·그저께 투구 수,
  최근 7일 부하, 투수의 평소 등판 비율로 예측하는 로지스틱 회귀. 같은 투수가 푹 쉬었을 때 대비 등판 확률(가용도)이
  30% 미만이면 휴식 권장, 65% 미만이면 주의. 실제로 2연투 뒤에는 6%, 전날 30구 이상이면 6%만 다시 나왔습니다(평소 46%)
- **선발**: 마지막 선발 후 3일 이내 휴식 권장, 4일 주의. 예상 선발은 팀의 최근 21일 선발 투수 가운데 "마지막 선발 후 일수별
  실제 선발 비율"이 가장 높은 투수 (9~10월 검증 1순위 58%, 2순위 안 80%)
- **부상 의심 신호**: 공개된 부상 기록이 없어 "등판 뒤 팀의 다음 3경기 안 1군 엔트리 말소"를 정답으로 씁니다(부진 강등도 섞임).
  직전 등판 주 직구가 최근 8경기 평균보다 3km/h 이상 느렸던 뒤에는 말소가 20%로, 구속 저하가 없을 때(7%)의 약 3배였습니다.
  구속 저하와 높은 말소 위험이 같이 있으면 최소 '주의'로 올립니다
- 웹의 **투수 컨디션** 탭에서 날짜·경기를 고르면 두 팀의 예상 선발(지난 경기는 실제 선발과 적중 여부)과 엔트리 투수별
  판정·피로도·최근 5일 투구 수·메모를 봅니다. 마지막 경기 다음 날은 "다음 경기 예측"으로, 두 팀을 직접 골라 봅니다
